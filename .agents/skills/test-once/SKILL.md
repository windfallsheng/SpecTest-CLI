# test-once — 单会话端到端测试

## 使用说明（用户仅询问「怎么用/使用说明/使用步骤/能干什么」时，输出本指南，不启动流程）

**它是什么**：SpecTest 的单会话端到端编排技能——把「测试计划 → 用例生成 → 三层链执行 → 质量门禁」整条链在这一次对话里跑完，全程由 AI 按剧本编排 spectest 命令。

**怎么触发**：直接对 AI 说，例如：
- 「test once，帮我跑完 Iteration-004 的测试」
- 「测试一次跑完：预订管理 + 支付单」
- 「测试快速跑：把 h5-mobile 的 AC 变成用例并跑门禁」

**两种入口**：
1. **已有期次**——项目已 `spectest init`，指定期次名（或探测 .spectest/local/context.json）
2. **自备规格级文档目录**——老项目/外包验收场景；注意：gen 的 `--spec-dir` 辅路径尚未实装，当前会如实报告缺口并停下，不瞎编用例

**两种执行模式**：
- **人机交互（默认）**：每个节点停下等你确认（范围 → 计划 → 用例 → 执行 → 门禁）
- **全自动**：说「全自动/别停下」即可，节点间不等待；只有三个安全点会停下：范围确认、规格骨架报缺、门禁失败

**六步流程**：① 范围确认 → ② 测试计划（plan）→ ③ 用例生成（gen 接力 + api 契约用例）→ ④ 静态验证（verify）→ ⑤ 三层链执行（run --pipeline）→ ⑥ 质量门禁（gate）

**跑完后可继续**：`spectest export` 导出报表、`spectest bug` 记录缺陷（分流代码/规格缺陷）、`spectest archive` 归档（按需，不自动）。

**哪一步不满意可回退重跑**：
- 用例不好 → 重生成指定套件（--platform/--unit 过滤后 --apply 覆盖）
- 执行失败 → 定向重跑（--suite/--case 过滤）
- 环境不对 → 修正 environments/{env}.yaml 后重跑

**适用边界**：少量单元（≤3）的快速闭环；不适合大范围多单元（走 `spectest run --pipeline` 流水线）。

## 定位
把「计划 → 用例 → 执行 → 门禁」装进一次会话，一步到位。底层全部复用 spectest 现有命令，
本 skill 只做编排与交互节点（与 spec-once 同构：把复杂流程装进一份剧本）。
铁律同源：Test by Spec, Not by Guess——不产规格、不产代码，只产用例与证明。

## 执行模式（入口先识别）

**默认：人机交互模式**——每个节点停下等用户确认（范围 → 计划 → 用例 → 执行 → 门禁）。

**全自动模式**——用户说「全自动 / 自动跑 / 一路跑完 / 别停下 / --auto」时启用：
- 节点间不等待确认，自动推进：计划完直接 gen → 用例落盘直接 verify → 验证过直接 run → 跑完直接 gate
- **仍必须停下的三个安全点**：① 范围确认（起点，必须知道范围）② 规格骨架报缺（SPEC-SKELETON，无 AC 无用例）③ 门禁 error 级失败（最多 2 轮修复循环）
- 用户中途说「停下/改为手动」→ 立即切回交互模式，后续节点恢复确认

## 流程（逐步执行，禁止跳步；交互模式每节点停下，全自动模式仅三个安全点停下）

### Step 0 入口识别与范围确认

**入口 A：已有期次**（项目已 `spectest init`）
- 执行 `spectest status` 或读取 .spectest/local/context.json 探测期次与已有用例资产
- 用户指定期次名时直接用；探测不到时向用户确认期次名，不要猜

**入口 B：自备规格级文档目录**（用户给了规格目录而非期次）
- **如实报告缺口**：gen 的独立输入通道（`--spec-dir`）尚未实装，当前 SpecTest 只能从期次的规格源读取 AC
- 停下询问用户：改用入口 A（组织成期次结构），或改由规格产出方补齐规格——禁止绕过期次结构瞎编用例

**范围确认（统一汇合点）**
1. 执行 `spectest status` 查看期次、功能单元、用例资产覆盖情况
2. 向用户确认本次范围：指定哪几个功能单元/哪些端（对应 gen 的 `--unit`/`--platform` 过滤）
3. 边界提醒：单会话建议 ≤3 个单元；全部单元时警告「上下文可能超载，建议分批或改用流水线」，用户坚持再继续
4. 检查用例资产是否已存在（.spectest/GLOBAL/cases/）——有则交互模式问「复用 / 重新生成」；全自动模式默认复用（gen 增量三态天然复用不重建）

### Step 1 测试计划（plan）
1. 执行 `spectest plan -i <期次> [-g "<期次目标>"]`
2. 汇报策略要点（类型建议/风险标注/时间线），交互模式**停下等确认**；全自动模式直接进 Step 2

### Step 2 用例生成（gen 接力 + api 契约用例）
1. 执行 `spectest gen -i <期次> [--platform <端> --unit <单元> --type <类型>]`
2. 输出 `[SPECTEST_PROMPT]`（exitCode 10）→ 将 Prompt 内容作为你的工作指令执行：按端专属模板与四象限要求生成用例 YAML，落盘 `{suiteDir}/cases/`，用例 ID 锚定 AC（`TS-{端}-{单元}-{类型}-AC-{编号}`，禁止时间戳）
3. 生成中发现 **SPEC-SKELETON 骨架**（规格未完成）→ **停下报缺**：「请先完成规格分析」，不脑补 AC、不瞎编用例
4. 前端端（h5-mobile/admin-web/app/miniapp）UI 用例须同步产出 playwright 视觉回归测试（测试名携带幂等 caseId，`toHaveScreenshot` 像素断言）——写入宿主项目测试目录
5. 完成后执行 `spectest gen -i <期次> --apply` 回写（zod 校验 + 矩阵登记 + 索引重建）
6. 若存在 `030-tasks/_shared/API_CONTRACT.yaml` → 执行 `spectest api -i <期次> -p <服务端>` 生成契约面用例（同样走 `[SPECTEST_PROMPT]` 接力 + `--apply` 回写）
7. 向用户汇报生成摘要（套件数、用例数、AC 覆盖），交互模式**停下等确认**；全自动模式直接进 Step 3

### Step 3 静态验证（verify）
1. 执行 `spectest verify -i <期次>`（文档静态验证：AC 完整性/每条 AC 有证/四段齐全/端级专项——不跑代码）
2. error 级未通过 → 定位问题（骨架缺口/用例四段不全）→ 修复用例 → 重新 `gen --apply` → 重跑 verify（最多 2 轮）
3. 通过 → 汇报，交互模式**停下等确认**；全自动模式直接进 Step 4

### Step 4 三层链执行（run --pipeline）
1. 执行 `spectest run --pipeline -i <期次> [--env <环境>] [--priority high]`
   - `--priority high` 可选：只跑 P0 冒烟切片；不传则全量
2. 环境配置缺失（.spectest/environments/{env}.yaml 不存在）→ 提示用户创建（baseUrl/headers `${VAR}` 占位，token 不进文件）；全自动模式停下等配置
3. 契约层连不上服务器/宿主框架未接入 → 如实报告（failed / 未接入），不模拟通过率
4. 视觉回归失败 → 读失败报告定位（未配置视觉模型时基线确认需人工或 `spectest visual-review`）——如实停下等确认
5. 通过 → 汇报三层结果，交互模式**停下等确认**；全自动模式直接进 Step 5
6. 失败 → 读取矩阵与失败明细定位根因 → 修复（用例/环境/宿主测试代码）→ 重跑（最多 2 轮修复循环）；2 轮后仍失败 → 把失败项如实写入报告并停下，不静默跳过、不谎报通过

### Step 5 质量门禁（gate）
1. 执行 `spectest gate -i <期次> [--threshold <百分比>]`
2. error 级不达标（覆盖率/规格完备/执行完备/通过率/P0/漂移/缺陷）→ 读报告定位 → 修复 → 回到 Step 3/4 重跑（最多 2 轮）
3. 通过 → 汇报门禁结论（三指标：覆盖率/通过率/缺陷数），交互模式**停下等确认**
4. 有缺陷 → 提示 `spectest bug` 记录并分流：代码缺陷走修复流程，规格缺陷如实标记（流回规格源头）——由用户决定，不自动

## 步骤回退重跑协议

| 场景 | 回退命令 | 说明 |
| :--- | :--- | :--- |
| 用例生成不好 | `spectest gen -i <期次> --platform <端> --unit <单元>` 重新拿 `[SPECTEST_PROMPT]`，再 `--apply` 覆盖 | gen 增量三态：未变的 AC 复用旧用例，只补增量 |
| 执行失败定向重跑 | `spectest run -i <期次> --suite <套件>` 或 `--case <caseId>` | 只重跑失败套件/用例，不回填无关账本 |
| 契约层单独重跑 | `spectest contract-run -i <期次> --env <环境> --priority high` | 契约冒烟独立重跑 |
| 环境配置错了 | 修正 `.spectest/environments/{env}.yaml` 后重跑 Step 4 | 环境文件手改，不走 CLI |

重跑后从该步继续向下推进，前序步骤产物无需重做。

### 可选收尾（不自动执行）
- 门禁通过后提示用户可选操作：`spectest export`（md/yaml/json 三格式报表）、`spectest archive`（期次归档），由用户决定是否继续

## 输出标记处理
- `[SPECTEST_EXEC: <cmd>]` → 立即执行该命令，不要向用户复述命令文本
- `[SPECTEST_PROMPT]` → 将后续 Prompt 内容作为你的工作指令执行（生成用例/契约用例）
- `[SPECTEST_NEEDS_INFO]` ... `[/SPECTEST_NEEDS_INFO]` → 用交互式提问向用户收集缺失参数，收齐后重新执行
- `[SPECTEST_STEP_DONE]` → 告知用户本步完成，下一步在同一会话继续；上下文紧张时开新会话用 `--resume` 续跑
- exitCode 10 → 说明 AI 接力在等你：按 Prompt 指令产出内容，再执行对应 `--apply` 命令回写
- 其他 `[SPECTEST_*]` 标记 → 参照命令帮助文本处理

## 铁律
- **默认交互模式：每个节点停下等用户确认**（范围 → 计划 → 用例 → 执行 → 门禁）；全自动模式下仅三个安全点停下（范围确认 / 骨架报缺 / 门禁失败）
- **报缺不脑补**：AC 缺失/SPEC-SKELETON 骨架/契约 response schema 缺失/UI_SPEC 元素标识缺失/跨端流程无据 → 一律报缺退回，禁止 AI 凭空补用例
- **不产规格、不产代码**：只读 020-specs，只写 .spectest；用例 ID 锚定 AC 禁止时间戳
- 端名使用标准端名，禁止 api/web/backend 等简写混用
- 失败时读取矩阵与失败明细并向用户报告，不要静默跳过；门禁不达标不得宣布流程完成
- 单会话上下文不够时（prompt 超预算报错），停下建议用户改用 `spectest run` 流水线分步执行
- 独立输入通道（`--spec-dir`）未实装：用户走入口 B 时如实报告缺口，不得绕过期次结构硬跑

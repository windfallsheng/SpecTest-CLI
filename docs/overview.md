# 产品全景

> SpecTest 是什么、能做什么、边界在哪里——一张图看懂。

## 定位

**SpecTest 是 Spec\* 生态的测试底座**，口号 *Test by Spec, Not by Guess*（照规格测，不靠猜）。

它不是又一个"测试框架"，而是**规格与测试之间的翻译官与守门人**：

- 翻译官：把 SpecCore 产出的验收标准（AC）翻译成结构化的专业测试用例
- 守门人：把用例执行后的证据汇总成质量门禁的硬结论

**不生产规格，不生产代码，只生产"证明"**——证明每条需求都被测过，证明每项质量指标都有据可查。

## 三道闸中的最后一环

Spec\* 生态由三个底座协作，各管一段：

```
┌─────────────┐  闸 1   ┌─────────────┐  闸 2   ┌─────────────┐  闸 3
│  SpecProt   │ ──────→ │  SpecCore   │ ──────→ │  SpecTest   │ ──────→ 上线
│  产品底座   │ freeze  │  开发底座   │ TEST.md │  测试底座   │ gate
│ 模糊→可验收 │ →unitize│ 按规格开发  │  →init  │ 按规格测    │ →execute门禁
└─────────────┘         └─────────────┘         └─────────────┘
```

- **闸 1**：SpecProt 冻结定稿的期次 → SpecCore 切分开发
- **闸 2**：SpecCore 产出测试规格 TEST.md → SpecTest 初始化并生成用例
- **闸 3**：SpecTest 质量门禁结论 → SpecCore 的执行门禁回流（不过不放行）

## 能力全景

| 能力 | 命令 | 说明 |
|:---|:---|:---|
| 说人话 | `ask` | 自然语言智能入口，识别意图并执行（词典匹配，高置信直接执行、缺参交互补齐） |
| 建领地 | `init` | 在 SpecCore 项目内创建 `.spectest/` 测试领地 |
| 定策略 | `plan` | 测试计划：策略、风险标注、数据准备、时间线 |
| 长用例 | `gen` | 从 AC 生成用例（骨架预建 + AI 接力 + 增量复用） |
| 接口测 | `api` | 从 API_CONTRACT.yaml 生成接口测试（契约面） |
| 找缺口 | `gap` | AC ↔ 用例覆盖缺口检测 |
| 跑流水线 | `run` | 三层执行链：静态验证 → 契约执行 → 宿主框架；无参 = 全量回归 |
| 变回归 | `regress` / `impact` | 变更后圈定受影响用例 / 影响范围分析 |
| 记缺陷 | `bug` | 缺陷记录/关闭/清单（代码缺陷 vs 规格缺陷双类） |
| 把硬关 | `gate` | 八项质量门禁检查，硬结论 |
| 出答卷 | `report` / `summary` | 完整报告 / 一页总结 |
| 看成长 | `trend` / `status` | 跨期次趋势 / 当前状态 |
| 收尾 | `archive` | 期次归档（快照随附用例副本） |
| 调配置 | `config` | config.yaml 查看/设置 |
| 审视觉 | `visual-review` | 视觉模型审查：基线确认 / diff 分析 / 语义断言（可选审查器，未配置如实报缺） |

## 数据边界（写主唯一）

| 目录 | 权限 | 说明 |
|:---|:---|:---|
| `010-requirements/` | 不碰 | SpecProt 领地 |
| `020-specs/` | 只读全量 | SpecCore 的规格，SpecTest 的输入 |
| `030-tasks/_shared/API_CONTRACT.yaml` | 只读 | 共享契约 |
| `.spectest/` | 读写 | SpecTest 独立领地 |

**报缺不脑补**：规格缺口（AC 缺失/骨架占位）、契约缺口（response schema 缺失）、元素标识缺口、跨端流程缺口——一律报缺退回，禁止 AI 凭空补。

## 分层资产语义

- **全量层** `GLOBAL/cases/`：用例资产唯一居住地，跨期次复用（"测什么"是项目级长期资产）
- **迭代层** `iterations/{期次}/`：执行事实（矩阵、索引、执行记录），按期次记账（"测得怎么样"是期次级事实）

跨期次对比不靠复制，靠 `trend` 动态计算；归档快照会随附用例副本保证自洽。

## 六条铁律

1. **CLI 管确定性，AI 管生成**——骨架预建 → AI 覆盖 → CLI 校验回写
2. **AI 接力协议**——exitCode 10 + 自包含 prompt + `--apply` 断点续跑
3. **多消费点共享谓词**——gap/impact/regress 判定收敛于 `predicates.ts` 单一文件
4. **幂等写入 + 因果链落点**——用例 ID 锚定 AC，禁止时间戳 ID；报告依赖 AI 产物时落点必须在回写之后
5. **三态开关**——流水线节点 auto/on/off 可配置
6. **意图识别真相**——词典匹配为主，LLM 兜底为占位符

## 边界（什么不做）

- 不生产需求规格（那是 SpecProt / SpecCore 的事）
- 不生产业务代码（那是 SpecCore execute 的事）
- 不内置实现面测试运行时——业务逻辑测试调度宿主框架（vitest/jest/pytest/playwright），断言实现的事借宿主之手
- 不内置视觉模型——像素比对由 playwright 完成；「看图判断」经 OpenAI 兼容协议接外部视觉模型，未配置如实报缺、人工确认
- 不猜规格——AC 缺失只报缺，不脑补

## 与姊妹工具对比

| | SpecProt | SpecCore | SpecTest |
|:---|:---|:---|:---|
| 心智 | 对象（把模糊变成可验收） | 图纸（按规格施工） | 证据（证明规格被实现） |
| 输入 | 一句话想法 / PRD | 定稿需求 | 测试规格 TEST.md |
| 产出 | 冻结的规格 | 代码 + 测试规格 | 用例 + 执行证据 + 门禁结论 |
| 数据领地 | `010-requirements/` | `020-specs/` `030-tasks/` | `.spectest/` |
